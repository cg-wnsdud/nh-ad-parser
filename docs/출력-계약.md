# 파싱 결과와 다음 심의 단계 출력 계약

## 세 산출물의 역할

`tools/parse.py`는 입력 하나마다 세 JSON을 만든다.

1. `parse/`: OCR·디지털 텍스트·좌표·레이아웃·VLM 후보를 담은 원시 `AdDocument`다.
2. `evidence/`: P1(`nh-ad-parse-evidence-v1`)이다. parse의 모든 필드를 유지하면서
   `line_ref`, 템플릿 선택 근거, 구분값 span, Reader/Judge 비교와 최종 선택 근거를 더한다.
3. `review-input/`: P3(`nh-ad-region-review-input-v1`)다. 영역을 심의 단위로 유지하고
   다음 단계가 사용할 `selected_text` 하나를 명시한다.

P2처럼 구분값별로 본문을 복제하고 다시 묶지 않는다. P3의 `label_index`는 텍스트를
복사하지 않고 영역과 줄 범위만 가리킨다.

## 템플릿과 구분값

카탈로그는 농협 제공 `광고 템플릿(근거규정x, 필수 여부).hwpx`의 실제 19개 표에서
생성됐다. 카탈로그에는 19개 템플릿과 127개 구분 항목이 있으며 원본 SHA-256을 기록한다.

템플릿 선택은 다음 순서다.

1. 상품군, 상품명 노출 여부, 파일명·본문의 강한 세부유형 힌트로 후보를 좁힌다.
2. 하나로 확정되지 않을 때만 Gemma가 후보 ID 중 하나 또는 `판단불가`를 선택한다.
3. 선택된 템플릿의 구분값만 VLM JSON Schema enum으로 허용한다.
4. 각 판정은 영역의 `line_from`~`line_to` span으로 저장한다. 한 영역에 여러 구분값과
   겹치는 span을 허용하되 텍스트 소유권은 늘 해당 영역 하나에만 있다.
5. `가입기간:` 같은 명시 표제와 긴 고정 고지문은 결정론적 근거로 보강한다.

템플릿 원본이 바뀌면 다음 명령으로 카탈로그를 재생성하고 테스트한다.

```bash
uv run python tools/build_template_catalog.py
uv run pytest -q tests/test_template_catalog.py
```

파싱 결과는 그대로 두고 템플릿 선택·구분 판정만 다시 실험할 때는 OCR을 재실행하지 않는다.

```bash
uv run python tools/build_review.py \
  --input out/<날짜>/<라벨>/parse \
  --out out/<날짜>/<라벨>
```

## OCR/VLM 중 하나를 고르는 정책

P1은 파서 원문과 VLM 판독을 모두 보존한다. P3는 다음 정책으로 하나만 전달한다.

| 상황 | P3 선택 | `needs_review` |
| --- | --- | --- |
| 파서와 VLM이 일치 | OCR/디지털 파서 원문 | `false` |
| Judge가 파서 원문 선택 | OCR/디지털 파서 원문 | Judge 상태에 따름 |
| Judge가 VLM 후보 선택 | VLM 영역 판독 | `true` |
| Judge 불확실·실패·merge | 파서 원문 폴백 | `true` |
| VLM 비교를 실행하지 않음 | 파서 원문 | 저신뢰 OCR이 있을 때 `true` |

VLM을 채택한 경우 `selected_source="vlm_judge"`와
`selection_status="judge_selected_vlm_requires_review"`를 함께 기록한다. P1의
`lines[].text`를 덮지 않기 때문에 채택 판단을 나중에 재검토할 수 있다.

## 유실 방지 불변식

- P1의 모든 영역/미배정 줄에는 문서 안에서 유일한 `line_ref`가 있다.
- P3의 `regions[].line_refs`와 `unassigned_text[].line_ref`는 P1 줄 전체를 정확히 한 번
  분할해야 한다.
- 누락·중복이 있으면 P3 JSON을 쓰지 않고 예외를 발생시킨다.
- 페이지 sweep의 `recovery_candidates`는 검증되지 않은 후보이므로 P3 본문에 섞지 않고
  `unverified_recovery_candidates`에 별도로 둔다.
