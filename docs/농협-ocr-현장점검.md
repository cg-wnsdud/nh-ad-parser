# 농협 폐쇄망 현장 점검 절차

규격: [농협-ocr-연동-규격.md](농협-ocr-연동-규격.md) · 전환 설계: [농협-ocr-전환-계획.md](농협-ocr-전환-계획.md)

## 0. 전제 — 왜 절차서가 필요한가

**ETL with LLM API 는 농협 폐쇄망 안에서만 호출할 수 있다.** 즉 현장 방문이 이 API 를
만질 수 있는 유일한 창구이고, 사실상 1회성이다. 사무실에서 "해보고 안 되면 다시"
가 안 된다. 그래서 규격 문서의 미확인 항목을 **현장에서 실행할 시험으로 미리 바꿔
두고**, 순서와 판정 기준을 정해서 들어간다.

## 1. 현장 목표 — 성능 측정이 아니라 데이터 확보

```text
현장에서   : 원본 응답 JSON 확보  +  5분짜리 계약 점검
사무실에서 : 변환 · 영역조립 · 라벨링 · PaddleX 대조 · 성능 판정
```

성능 판정(골드 문장 회수율 대조)은 눈으로 안 되고 시간이 걸린다. 반면 **원응답 JSON
만 있으면 나머지 전부를 사무실에서 무한히 재생**할 수 있다. 짧은 현장 시간을 채점에
쓰지 않는다.

> **현장에서 반드시 챙겨 나올 것: 대표 입력 4~5건의 원응답 JSON.**
> 이게 없으면 또 가야 한다.

## 2. 가장 먼저 확인할 것 — 결과 반출 가능 여부

여기서 준비물이 갈린다. **방문 전에 확인해야 한다.**

| 반출 가능 | 반출 불가 |
|---|---|
| 원응답만 받아 나오면 됨 | **현장에서 판정까지 끝내야 함** |
| 준비물: 프로브 + 샘플 | 준비물: 프로브 + 샘플 + **PaddleX 기준선 + 골드 문장 + 대조 스크립트** 전부 반입 |

## 3. 방문 전에 받아야 하는 것

호출에 **반드시** 필요한 것은 위 세 개다. 하나라도 없으면 현장에서 아무것도 못 한다.

| 항목 | 왜 필요한가 |
|---|---|
| **① 접속 주소 (IP:Port)** | 없으면 아무것도 못 한다. 가이드 예시는 `58000` 포트 |
| **② 인증 필요 여부** (필요하면 계정) | 로그인 API 가 "인증 미들웨어 설정이 필요한 경우" 로 되어 있어, 안 켜져 있으면 계정 자체가 불필요하다 |
| **③ `ws_id`** | `tr_data` 의 필수 필드. **AgileSoDA 측이 생성해 전달**한다 (2026-09-08 회신). 우리가 만들지 않는다 |
| **현장 PC 에 Python 이 있는지** | 없으면 프로브가 못 돈다 → Windows embeddable Python 반입 또는 `curl` 대체안 필요 |
| 노트북·USB·코드 반입 절차 | 반입이 막히면 현장 PC 에서 손으로 타이핑해야 한다 |
| 결과 파일 반출 가능 여부 | §2 |
| 테스트 가능 시간 | 시험 항목을 그 안에 맞춰 자른다 |

## 4. 반입물 체크리스트

- [ ] **`tools/etl_probe.py` 한 파일** — 표준 라이브러리만 쓴다. `pip install` 불필요
- [ ] **샘플 입력 4~5건** — 농협 프로젝트 실제 입력에서 성격이 다른 것을 고른다
      - 이미지 단건 (PNG) — 이미지 지원 여부 확인용
      - 세로로 긴 스크롤 광고 (실측 1122×6429 급) — 축소 문제 확인용
      - 표가 있는 문서 — `cells`·병합셀 확인용
      - 텍스트 레이어 있는 PDF — `ocr_only` 비교용
      - 작은 글씨(유의사항·심의필)가 있는 문서 — fine-print 회수 확인용
- [ ] **PaddleX 기준선** — 같은 샘플의 현재 산출물 (`out/<날짜>/<라벨>/`). 반출 불가일 때 현장 대조용
- [ ] **이 문서 인쇄물** — 현장 PC 에서 문서를 못 열 수 있다
- [ ] (반출 불가 시) 골드 문장 목록 + 대조 스크립트

## 5. 방문 전 리허설

현장에서 스크립트 버그를 만나면 되돌릴 수 없다. 목 서버로 전 구간을 미리 돌린다.

```bash
python tools/etl_mock.py python tools/etl_probe.py run \
    --base-url http://127.0.0.1:58999 --ws-id WS0001 \
    --author me --input <샘플파일>
python tools/etl_probe.py summary
```

목 서버는 규격 문서 기준의 **추측**이다. 확인하는 것은 "규격이 맞는가" 가 아니라
"우리 스크립트가 죽지 않는가" 다.

## 6. 현장 절차 — 위에서부터 순서대로

시간이 부족하면 **T1 · T3 · T4 (PDF 왕복 → 계약 점검 → PNG 업로드) 는 반드시** 한다.
나머지는 남는 시간에. T1' · T2 는 문제가 생겼을 때만 쓰는 우회로다.

| # | 시험 | 명령 | 판정 |
|---|---|---|---|
| **T1** | **PDF 1건 왕복** ★ | `run --ws-id <받은 값> --author me --input sample.pdf` | `file_paths` 수신 → `chunk_status` 002 → **원응답 저장**. 인증이 꺼져 있으면 이 한 줄로 끝난다 |
| T1' | (T1 이 401/403 일 때만) 로그인 | `login --user-id U --user-pw P` 후 T1 재실행 | 인증 미들웨어가 켜져 있던 경우 |
| T2 | (`ws_id` 가 안 통할 때만) 워크스페이스 확인 | `ws-list --user-id U` | 받은 `ws_id` 가 목록에 있는가 |
| **T3** | **계약 점검** ★ | `summary` | 줄 confidence / 표 `lines` / `cell_info` / bbox 형태 |
| **T4** | **PNG 직접 업로드** ★ | `run --input sample.png` | 되는가. 안 되면 **PDF 변환 단계 추가 확정** |
| T5 | 긴 스크롤 | `run --input long_scroll.*` | `width`/`height` 가 어떻게 나오는가. 작은 글씨가 살아있는가 |
| T6 | 표·병합셀 | `run --input table_doc.pdf` → `summary` | 병합셀 `cell_info` 가 `[r0,r1,c0,c1]` 양끝포함인가 |
| T7 | `author` 필수 여부 | `run --omit-author ...` | 성공하면 선택, 실패하면 필수 (규격 M6) |
| T8 | 에러 형식 | 잘못된 `--file-path` 로 `poll`, 파라미터 누락 | `result.code` 형과 `detail` 형 둘 다 재현 |
| T9 | 소요 시간 | T1 폴링 로그의 회차·간격 | 문서 1건 소요 → 배치 설계 근거 |
| T10 | 임계값 영향 | `run --prj-config '{"dla_score_th":0.3}'` | 기본 0.5 대비 회수/오검출 변화 |
| T11 | 콜백 | 수신 서버를 띄울 수 있을 때만 | 안 되면 **폴링 전용 설계로 확정** |

각 단계는 요청·응답을 `probe-out/<타임스탬프>/` 에 전부 저장한다. **화면만 보고
넘어가지 않는다.**

## 7. 현장에서 즉시 기록할 것

프로브가 저장하지 못하는 것들이다. 인쇄물에 손으로 적는다.

- [ ] 접속 주소·포트, 인증 필요 여부
- [ ] `ws_id`, 계정명
- [ ] 각 시험의 성공/실패와 **에러 메시지 원문**
- [ ] T1 의 문서 1건 소요 시간
- [ ] 이미지 업로드 가능 여부 (T4) ← 가장 중요
- [ ] 결과 파일 반출 승인 여부·절차
- [ ] 다음에 다시 올 수 있는지, 원격 접속이 열릴 여지가 있는지

## 8. 현장 후

1. 원응답으로 `tests/test_etl_dla_convert.py` 픽스처를 **실물로 교체** — 지금 픽스처는
   가이드 예시라 추측이 섞여 있다
2. `cell_info` 양끝포함 해석 확정 (T6)
3. 변환기 보정 → 영역조립까지 통과시키기
4. PaddleX 대조: 골드 문장 회수율 (현재 기준선 236/242), 표 구조 유지, fine-print
5. 격차 G1·G11 처리 방침 확정 → 전환 계획 갱신
6. 전환 판단. 통과하지 못하면 격차를 **수치로** 정리해 농협·AgileSoDA 에 회신

## 9. 현장에서 답이 나오는 질문 / 그래도 물어야 하는 질문

| 현장에서 측정되는 것 | 회신으로 받아야 하는 것 |
|---|---|
| 이미지 지원 여부 (T4) | 지원 확장자 **목록**, 파일 크기·페이지 상한 |
| 인증 필수 여부 (T1/T1') | 토큰 유효기간·갱신 방식 |
| `author` 필수 여부 (T7) | `author` 가 무엇에 쓰이는지 |
| 에러 응답 형식 (T8) | **에러 코드 정의표** |
| 문서 1건 소요 시간 (T9) | 동시 요청 허용 수 |
| 표 줄·셀 구조 (T3/T6) | 표 줄 단위 결과를 주는 옵션이 있는지 |
| — | **VLM 서비스 제공 여부** (현장에서 확인 불가) |

전체 질문 목록은 [전환 계획 §7](농협-ocr-전환-계획.md).
