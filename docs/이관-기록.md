원본 저장소에 실험 산출물과 코드가 뒤엉켜 더 진행하기 어려웠다. 실측:

## 무엇을 가져왔나

파싱 진입점 `pipeline.process_file` 이 **실제로 끌어오는 모듈만** 의존성 그래프로
추적해 21개, 6,423줄을 가져왔다. 나머지 14모듈(라벨링·추출·내보내기)은 두고 왔다.

경계를 눈으로 정하지 않고 그래프로 정한 이유: 원본은 주석·문서에 다른 모듈 이름이
자주 등장해서(`regions.py` 가 `vlm_judge` 를 문서에서 언급하지만 import 는 안 한다)
읽기로 판단하면 틀린다.

## 테스트

원본 46개 중 **파싱 모듈만 참조하는 29개**를 가져왔다(라벨링·추출 모듈을 import 하는
것은 제외). `test_cards.py` 는 쓰지 않는 `vlm_judge` import 한 줄만 지우고 가져왔다.

`test_role_evidence.py` 는 **가져오지 않았다.** `pipeline.judge_region_roles` 를
monkeypatch 하는데 그 함수는 `vlm_judge.py`(범위 밖)에 있고, **원본에서도 이미 3건
전부 실패하던 죽은 테스트**다.

```
원본:   413 passed, 7 failed   (test_digital_lines_structure 3 · test_role_evidence 3 · test_role_prompt_context 1)
새 것:  176 passed, 0 failed, 37 skipped
```

37건 skip 은 전부 "샘플 PDF 없음" — 고객 자료를 가져오지 않았기 때문이다.
`nh-data` 를 붙이면 돌아간다.

## 동작이 같은지 확인한 방법

같은 입력(`올원e적금.png`)을 원본과 새 저장소에서 각각 파싱해 대조했다.

```
줄 수      새 73  구 73     글자 동일 True
영역 수    새 38  구 38     영역좌표 동일 True
줄 좌표    동일 True
글자 차이  0건
```

**완전히 동일하다.** 재구조화가 파싱 동작을 바꾸지 않았다.

## 이관 시 걸렸던 것

1. **`document-processor` 를 `pyproject.toml` 에 못 박으면 `uv sync` 가 실패한다.**
   사설 저장소라 HTTPS 로 못 받는다. 지연 import 라 빼도 PDF·이미지는 정상이다.
2. **의존성 그래프에서 `vlm_cache` 를 놓칠 뻔했다.** `gemma_client` 가
   `from . import vlm_cache` 형태로 부르는데 `from .X import` 만 찾는 정규식에
   안 걸렸다. 20개인 줄 알았던 것이 21개였다.
3. **`regions.py` / `llm_view.py` 의 `vlm_judge` 언급은 주석이었다.** import 로 착각해
   범위를 잘못 넓힐 뻔했다.
