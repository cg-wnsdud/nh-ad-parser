# 테스트 실행 지침

새 입력을 파싱해볼 때 **어떤 AI·사람이 실행하든** 결과를 `out/` 아래 같은 규격으로
남기기 위한 지침이다. 실행 주체나 개발 도구와 무관하게 적용한다.

## 사전 조건

- 사내 WireGuard VPN 연결 (PaddleX·Gemma 서버 응답에 필요)
- `.env` 에 `PADDLEX_URL` / `GEMMA_URL` / `GEMMA_MODEL` 설정 완료
- `GEMMA_MODEL` 접두어가 틀리면 VLM 호출은 400 으로 죽는데 OCR 은 멀쩡히 돌아
  산출물이 그럴듯하게 나온다(전례 있음). 의심되면 `GEMMA_URL` 을 `/models` 로
  바꿔 GET 해서 현재 모델명을 확인한다. — [README.md](../README.md) 참고

## 실행 명령어

```bash
uv run python tools/parse.py --input <파일 또는 폴더> --out out/<날짜>/<라벨> --preview
```

- `--input` : 파일 하나 또는 폴더(폴더면 `.pdf .png .jpg .jpeg .hwp .hwpx` 전부 처리)
- `--only <부분문자열>` : 폴더 입력일 때 파일명으로 필터링
- `--preview` : 쪽 이미지 축소본도 `pages/` 에 남긴다. **항상 켠다** — 원본 대조 검증용

## 출력 규격 — `out/<YYYY-MM-DD>/<run-label>/`

```
out/
  2026-09-08/
    samples-full/
      parse/<원본파일명>.json
      evidence/<원본파일명>.json
      review-input/<원본파일명>.json
      pages/<원본파일명>_p<N>.jpg   (--preview 사용 시)
```

### 규칙

1. **날짜 폴더명은 `YYYY-MM-DD` 고정**(한국시간, 실행일 기준). `20260908`,
   `verification_20260908` 처럼 실행자마다 다른 포맷을 쓰지 않는다 — 지금
   `out/` 안에 `verification_20260908` / `verification_20260908_hwp` /
   `verification_20260908_pdf` 가 섞여 있어 날짜순으로 훑어볼 수가 없다.
   이 지침 이후로는 위 규격으로 통일한다. (기존 폴더는 남겨두되 그대로 두고,
   새로 만들 때만 규격을 지킨다.)
2. **`run-label` 은 무엇을 테스트했는지 알 수 있는 kebab-case.**
   예: `samples-full`, `e-savings-only`, `hwp-check`, `pdf-card-product`.
   `test`, `tmp`, `temp1` 처럼 내용을 알 수 없는 이름은 쓰지 않는다.
3. `--out` 값은 항상 `out/<날짜>/<라벨>` 형태로 지정한다. `out/` 바로 아래나
   `out/parse/` 처럼 날짜 없이 흘리지 않는다.
4. 같은 날 같은 라벨을 다시 돌릴 때:
   - 같은 입력을 재현/재검증하는 것이면 덮어써도 된다.
   - 이전 결과와 비교하고 싶으면 라벨 뒤에 `-v2`, `-v3` 를 붙여 구분한다.
     (VLM 을 쓰는 단계는 같은 입력에도 결과가 흔들릴 수 있다 —
     [README.md 알려진 한계](../README.md#알려진-한계) 참고)
5. 폴더 전체를 한 번에 돌릴 때는 라벨을 폴더 성격으로 짓는다
   (예: `samples/` 전체 → `samples-full`).

## 실행 후 반드시 확인할 것

콘솔 출력에서:
- `N/N 건 성공` — 실패 건수가 0인지
- `미배정줄` 표시가 뜨지 않는지 (뜨면 결함이다 — "모든 글자는 어딘가에
  남는다"는 게 이 파서의 기본 원칙, [README.md](../README.md) 참고)

산출물 JSON에서 (`pages[].parse_status`):
- `"ok"` 인지 확인. 다르면 해당 쪽 파싱이 실패한 것.
- `evidence/`에서 선택 템플릿과 `template.labeling_status`를 확인.
- `review-input/`에서 `needs_review_region_count`와 각 영역의 `selected_source`를 확인.

## 산출물 확인 시 흔한 실수

- **Windows 콘솔이 한글을 깨뜨릴 수 있다.** JSON 파일 자체는 UTF-8 로
  정상 저장되어 있으니, 터미널에 그대로 출력해서 판단하지 말고 파일을 열어서
  확인하거나 `PYTHONIOENCODING=utf-8` 등으로 맞춘 뒤 확인한다.
- **`region.role` 은 규칙 기반 폴백값이다.** 최종 확정 라벨로 신뢰하지 않는다
  ([README.md "범위"](../README.md#범위--여기-없는-것) 참고).

## 예시

```bash
uv run python tools/parse.py --input samples --out out/2026-09-08/samples-full --preview
```

```
▶ [예금성상품-적금] 올원e적금.png
  쪽 1 / 영역 38 / 줄 73 / 20초  → out\2026-09-08\samples-full\parse\[예금성상품-적금] 올원e적금.json

1/1 건 성공
```

결과:

```
out/2026-09-08/samples-full/
  parse/[예금성상품-적금] 올원e적금.json
  evidence/[예금성상품-적금] 올원e적금.json
  review-input/[예금성상품-적금] 올원e적금.json
  pages/[예금성상품-적금] 올원e적금_p1.jpg
```
