# ETLwithLLM 연동 방향 검토 요청

## 요청드리는 결정

농협 DLA/OCR을 사용하면서 광고 파싱 후처리를 연결하는 방법을 세 후보로 구현했습니다.
현재 단계는 방향 결정용이며 농협 반입 완성본은 아닙니다.

### 추천

1. **A안(외부 API)을 기준선으로 유지**합니다.
2. AgileSoDA에 `transform()`의 호출·결과 저장 계약을 확인하고, 가능하면 **B안**을
   운영 후보로 선택합니다.
3. `CUSTOMIZE`는 전처리 뒤 DLA가 이어진다는 답을 받기 전에는 선택하지 않습니다.
4. Knowledge Lake가 최상위 호출자라는 요구가 있을 때만 기존 `kl_parser` 이식을
   별도 작업으로 진행합니다.

## 후보별 의미

| 후보 | 하는 일 | 결정에 필요한 답 |
|---|---|---|
| A 외부 API | `/etl/auto/start`로 DLA 요청 후 JSON을 받아 우리 파이프라인 실행 | 우리 실행기를 둘 농협 내부 위치 |
| B transform | ETL의 DLA 완료 뒤 같은 플랫폼 프로세스에서 우리 파이프라인 실행 | transform 호출 시점·입출력 경로·의존성 설치 방법 |
| C CUSTOMIZE | extract 훅의 실제 인자와 후속 동작만 관찰 | 외부 `customize` 지원 여부, extract 뒤 DLA 연결 방법 |
| KL Custom Parser | KL의 `/parsing`·polling·ZIP 계약 제공 | 최상위 업무 흐름이 KL에서 시작하는지 |

## 문서에서 확인된 결정적 근거

- 외부 API p.29의 `extractType` 공개값은 `all`, `dla`, `parser`뿐입니다.
- p.53 내부 `CUSTOMIZE` 분기는 `extract()`만 호출하고 `dla_task()`를 호출하지 않습니다.
- p.54 `transform()`은 `dla_result_path`를 받으므로 DLA 결과 후처리 위치라는 점은
  확인됩니다.
- `implements/api/`는 ETL 서버에 선택적인 API를 추가하는 기능이며, KL Custom Parser
  API와 자동으로 연결되지 않습니다.

## 공급사에 확인할 질문

1. 외부 `prj_config.extractType`에서 `customize`를 지원합니까?
2. `CustomExtension.extract()` 완료 후 기본 DLA를 이어 실행하는 공식 API가 있습니까?
3. `extractType=dla`일 때 `transform()`은 항상 호출됩니까?
4. `dla_result_path`는 파일입니까, 디렉터리입니까? Default JSON 위치는 어디입니까?
5. `transform()` 산출물을 어느 경로에 써야 ETL 결과 목록·callback에 포함됩니까?
6. `CustomExtension` import 경로와 구현체 로딩 규칙을 포함한 원본 템플릿을 받을 수
   있습니까?
7. ETL 이미지에 프로젝트 wheel과 외부 Python/system 의존성을 설치하는 공식 절차는
   무엇입니까?
